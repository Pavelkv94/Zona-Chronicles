# I02B — evidence

Снято с чистого прогона на PostgreSQL 17.5 (`docker compose up -d postgres`), seed 42.
Каждый файл получен исполнением, а не составлен вручную.

| Файл | Что это |
| --- | --- |
| `initial.json` | Канонический снимок мира сразу после порождения из seed 42, с checksum. Одна строка canonical JSON — та же форма, что проверяет A1 из I01 |
| `events.jsonl` | Канонический журнал: sequence, event_id, тип, мировое время, акторы, `event_checksum` |
| `scheduled-actions.tsv` | Расписание после прогона: оба действия помечены выполненными, а не удалены (C2) |
| `final-world.json` | Версия мира, последняя sequence и мировое время после обработки |
| `tick.txt`, `events.txt`, `final-state.txt` | Вывод CLI из того же прогона |

## Что видно в этих файлах

**Мир пошёл сам.** Два агента вышли на маршрут командами, `world tick --advance 40` завершил
оба без участия человека, мировое время сдвинулось с 06:00 на 06:40 — на длительность пути, а
не на величину «тика». Время двигают события (ADR-004).

**Порядок обработки не случаен.** У обоих действий совпадает `due_at`, поэтому очередь
разрешилась следующим ключом — `entity_id`: `agent:kite` раньше `agent:rook`, и это
воспроизводится между прогонами (C4).

**Расписание — часть канонического состояния.** Обе строки `scheduled_actions` выведены из
событий `journey.started` (их `action_id` равен `event_id` причины), и обе помечены
выполненными, а не удалены: каноническим является только незавершённое расписание, история
обработки остаётся для расследования.

## Чего здесь НЕТ и почему

`world-health.json`, `causal-chains.json`, `interventions.json` из шаблона
`10_ITERATION_MASTER_PLAN` §3 не приложены: в мире пока две механики и ни одного
контроллера — эти файлы описывали бы то, чего не существует. Появятся вместе с тем, что они
описывают.
