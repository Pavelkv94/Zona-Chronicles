## Пункт 4 — новый механизм можно добавить без правки несвязанных packages

**Измерено, а не оценено.** Проба: в каталог `WORLD_EVENT_TYPES` добавлен тип `probe.happened`
с payload-схемой и вариантом, после чего `pnpm typecheck` показывает, кого система ЗАСТАВЛЯЕТ
измениться. Проба выполнена на выброшенной ветке и откачена.

Результат — правки требуют только связанные места:

| Package | Требует правки | Почему |
| --- | --- | --- |
| `packages/contracts` | да | каталог событий живёт здесь |
| `packages/domain` | да | `evolve` обязан обработать новый факт |
| `apps/web` | да | подпись события для зрителя |
| `apps/api`, `apps/worker`, `apps/cli` | **нет** | ни одной правки |
| `packages/persistence`, `packages/projections` | **нет** для типа без своего состояния |
| `packages/simulation`, `packages/representation`, `tools/**` | **нет** | ни одной правки |

Ограничение измерения названо честно: проба добавляла ТИП СОБЫТИЯ, а не механику целиком.
Механика с собственным состоянием и командой потребует ещё домена, персистентности и проекции —
но это связанные звенья, а не несвязанные packages, и Gate A требует именно второго.

### Побочная находка пробы: обещание A8 было пустым

Проба измеряла границы, а нашла дефект, который никакая роль ревью не нашла за три раунда.

`WorldEvent` был union-ом, выписанным ВРУЧНУЮ рядом с каталогом. Тип, добавленный в
`WORLD_EVENT_TYPES`, в обе payload-карты и в схему union, но не в это перечисление, не ломал ни
одного потребителя: **`pnpm typecheck` давал ноль ошибок во всём workspace**, а новое событие
молча выпадало бы из ленты. Именно от этого поставлен `assertNeverWorldEvent`, и его докстринг
обещал: «добавление типа события ломает компиляцию каждого потребителя, который его не
обработал (A8)».

Мест, не принуждённых типами, было четыре из шести.

Починено: `VARIANT_SCHEMAS` объявлен полным по построению (`satisfies Record<WorldEventType, …>`),
схема union собирается ИЗ каталога, а `WorldEvent` выводится отображением по `WorldEventType` —
отображение сохраняет дискриминатор, поэтому `switch` по-прежнему сужается до `never`.

Проверено мутацией, все направления:

| проба | результат |
| --- | --- |
| тип добавлен полностью, код ДО починки | ноль ошибок вне контрактов и подписи на экране |
| тот же тип, код ПОСЛЕ починки | `evolve.ts: ... is not assignable to parameter of type 'never'` |
| тип в каталоге без варианта | ломается в самих контрактах: `does not satisfy Record<…>` |
| убрана ветка `switch` в проекции | `observer-fold.ts: ... is not assignable to type 'never'` — дискриминатор цел |
| порядок вариантов union разошёлся с каталогом | падает новый runtime-страж в contract-тесте |
