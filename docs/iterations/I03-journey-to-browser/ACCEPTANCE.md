# I03 — ACCEPTANCE

Итерация: I03 «Journey до браузера»
Заморожено: 2026-08-23, до начала реализации.
Нумерация продолжает I01 (A1–A11), I02A (B1–B10), I02B (C1–C12): здесь **D1–D14**.

Каждый критерий исполняем. «Проверено вручную» приёмкой не является. Каждый новый инвариантный
тест сопровождается записанным выводом мутационной пробы, прогнанной ИЗОЛИРОВАННО
(`08_TDD_AND_AGENT_WORKFLOW` §7), с проверкой ОБОИХ направлений.

## D1. Мир идёт сам, без человека и без зрителя

**Given** запущенный worker и мир с начатым путём
**When** проходит реальное время, и ни один человек не запускает команд
**Then** путь завершается,
**And** мировое время сдвигается на длительность пути, а не на величину «тика»,
**And** журнал тот же, что при пошаговом `world tick --advance` на ту же длительность.

Последняя строка — то, ради чего критерий существует: скорость мира влияет на то, КОГДА событие
произойдёт по стенным часам, а не на то, каким оно будет (SIM-01).

## D2. Скорость мира — часть versioned ruleset, а не константа кода

**Given** два прогона с РАЗНОЙ скоростью мира и одинаковым seed
**When** оба доведены до одного и того же мирового времени
**Then** канонический журнал побайтово одинаков,
**And** скорость НЕ входит в `deterministic_runtime_profile`.

## D3. Наблюдатель не влияет на мир

**Given** мир, идущий сам
**When** к нему подключаются ноль, один или десять SSE-клиентов, и клиенты отключаются
**Then** канонический журнал не отличается от журнала прогона без единого подключения.

Проверяется сравнением журналов, а не отсутствием write-маршрутов: отсутствие маршрутов — D4,
здесь проверяется отсутствие КОСВЕННОГО влияния.

## D4. Публичное API не содержит write-маршрутов

**Given** собранный observer API
**Then** ни один зарегистрированный маршрут не отвечает на POST/PUT/PATCH/DELETE,
**And** это установлено обходом таблицы маршрутов, а не списком в тесте.

## D5. Observer path не читает канонические таблицы

**Given** роль БД `zona_api`
**When** API обслуживает любой публичный запрос
**Then** ни один запрос не обращается к `world_events`, `worlds`, `agents`, `command_results`,
`scheduled_actions`, `world_snapshots`,
**And** попытка такого чтения отвергается ПРАВАМИ роли, а не отсутствием кода.

## D6. Проекция строится из outbox и переживает перезапуск

**Given** мир с историей и построенная проекция
**When** процесс сборщика проекций убит и запущен заново
**Then** проекция догоняет журнал ровно один раз на событие: без пропусков и без дублей,
**And** `projection_sequence` строго возрастает.

## D7. Проекция пересобирается с нуля и даёт тот же результат

**Given** проекция, построенная инкрементально до `projection_sequence = N`
**When** таблицы проекции очищены и она собрана заново из того же outbox
**Then** результат побайтово совпадает с инкрементальным,
**And** это единственный поддерживаемый способ починки проекции: правка её строк не является
восстановлением (проекция не источник факта).

## D8. Snapshot endpoint самодостаточен

**Given** мир с историей
**When** клиент запрашивает `GET /v1/world/snapshot`
**Then** ответ содержит карту, агентов и `projection_sequence`, с которой можно продолжить поток,
**And** ответ проходит `decodeObserverWorldSnapshot`,
**And** ответ НЕ содержит ни одного канонического поля (проверено contract-тестом I03).

## D9. SSE возобновляется по `Last-Event-ID`

**Given** клиент, получивший события до `projection_sequence = K`
**When** он переподключается с `Last-Event-ID: K`
**Then** он получает события строго после K, по одному разу каждое, в порядке возрастания,
**And** ни одно событие между K и переподключением не потеряно.

## D10. Утраченное окно retention даёт явный `reset_required`

**Given** клиент, переподключающийся с `Last-Event-ID`, которого проекция уже не хранит
**Then** он получает управляющее сообщение `reset_required` с ближайшей доступной позицией,
**And** НЕ получает ленту с начала молча.

## D11. Восстановление состояния не зависит от истории SSE

**Given** зритель с открытой страницей
**When** страница перезагружена
**Then** состояние восстановлено запросом snapshot, а не проигрыванием истории потока,
**And** отключение SSE целиком оставляет страницу работоспособной в режиме без обновлений.

Это OPS-02, и он проверяется отключением потока, а не рассуждением.

## D12. Отказ несвязного маршрута виден и объясним

**Given** локация `loc:relay-station`, к которой не ведёт ни один маршрут
**When** предпринята попытка начать путь к ней
**Then** команда отвергнута названной причиной,
**And** отказ виден в CLI как отказ, а не как отсутствие результата.

## D13. E2E: путь виден в браузере и переживает перезагрузку

**Given** запущенные worker, API и экран
**When** путь начат командой CLI
**Then** агент на карте меняет состояние на «в пути» БЕЗ перезагрузки страницы,
**And** событие появляется в ленте,
**And** после завершения агент оказывается в конечной локации,
**And** перезагрузка страницы восстанавливает то же состояние,
**And** увиденное совпадает с каноническим журналом (`world events`).

## D14. Чтение, становящееся артефактом, выполняется в одной транзакции

**Given** мир, изменяемый параллельно
**When** строится проекция или снимок
**Then** прочитанное состояние соответствует ОДНОЙ версии мира,
**And** `loadWorldState` не может вернуть состояние, которого в мире не было (BLOCKER 2 I02B).

## Что НЕ является приёмкой

- зелёные тесты API без запущенной базы под ролью `zona_api`;
- «страница отрисовалась» без сверки увиденного с каноническим журналом;
- SSE, проверенный одним подключением без разрыва;
- проекция, проверенная только инкрементально, без пересборки с нуля;
- «мир идёт» с горизонтом, который двигает запрос зрителя.
