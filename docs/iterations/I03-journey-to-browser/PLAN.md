# I03 — PLAN

Итерация: I03 «Journey до браузера»
Вход: I02B (`d6a50ba`)
Дата: 2026-08-23

## 1. Гипотеза

Один факт проходит через весь стек и понятен зрителю. До сих пор мир наблюдался только из
терминала: `world events` печатает журнал, `world state` — состояние. После I03 тот же факт
виден на экране в браузере, и увиденное совпадает с каноническим журналом.

Это первая итерация, после которой у проекта есть ПРОДУКТ, а не только движок.

## 2. Observable demo

```sh
export DATABASE_URL=postgres://zona:zona_local_dev_only@localhost:5432/zona
pnpm world migrate && pnpm world init --seed 42

# мир идёт сам: worker двигает время по скорости мира, без участия зрителя
pnpm worker &

pnpm api &          # observer API, read-only
pnpm web &          # экран

# открыть http://localhost:3000
#   - карта: четыре узла, рёбра маршрутов, агенты на узлах
#   - лента: journey.started / journey.completed по мере появления
# начать путь из CLI:
pnpm world run --agent agent:rook --route route:yard-to-bridge
#   - агент на карте становится "в пути"
#   - в ленте появляется journey.started БЕЗ перезагрузки страницы (SSE)
#   - через время мира появляется journey.completed, агент оказывается на мосту
# перезагрузить страницу — состояние восстанавливается из snapshot API, не из SSE
```

**Что демо обязано показать, а не просто отработать:** экран не влияет на мир. Закрытая вкладка,
десять вкладок или ноль — журнал одинаков. Это PR-01 и PR-04, и проверяется отдельно.

## 4. Scope

1. **Долг I02B — мир идёт сам.** `runWorldTick` в цикле worker-а; горизонт вычисляется из
   реального прошедшего времени и коэффициента скорости мира. Коэффициент — в versioned ruleset,
   не в коде и не в env.
2. **Долг I02B — BLOCKER 2.** `loadWorldState` читает мир в ОДНОЙ транзакции.
3. **Расширение контента:** обратные маршруты, чтобы мир не «заканчивался» после нескольких
   переходов. `loc:relay-station` остаётся несвязной намеренно — под критерий отказа.
4. **Проекции** (`packages/projections`): read models карты и ленты, своя `projection_sequence`,
   свои таблицы. Строятся из `outbox`, а не из канонических таблиц.
5. **Observer API** (`apps/api`): `GET /v1/world/snapshot`, `GET /v1/map`, `GET /v1/events`,
   `GET /v1/stream` (SSE, resume через `Last-Event-ID`). Роль БД — `zona_api`, без доступа к
   каноническим таблицам.
6. **Экран** (`apps/web`, Next.js): карта узлов и лента событий. Читает только `/v1/*`.
7. **Playwright journey scenario:** путь начат — виден на карте — завершился — перезагрузка
   страницы восстанавливает состояние.

## 5. Out of scope

- поиск, летопись, профили агентов, сцены — I16;
- admin API (`/internal/*`) сверх того, что уже есть;
- визуальный дизайн сверх читаемости; анимации;
- аутентификация зрителя — публичный мир анонимен до I17;
- любые механики сверх `journey.start`/`journey.complete`.

## 7. Инварианты, которые нельзя нарушить

1. **Observer path не читает канонические таблицы.** Ни API, ни проекции при ОБСЛУЖИВАНИИ
   запроса. Построение проекции читает `outbox`, а не `world_events` напрямую.
2. **Публичный API не содержит write-маршрутов.** Проверяется `app.printRoutes()`, не намерением.
3. **Зритель не влияет на мир.** Ни числом подключений, ни их отсутствием, ни `Last-Event-ID`.
4. **Скорость мира не входит в `deterministic_runtime_profile`** — она свойство темпа, а не
   детерминизма.
5. **Проекция не является источником факта.** Расхождение проекции с журналом — сбой проекции,
   и восстанавливается она пересборкой, а не правкой.

## 8. Порядок работ

1. Контракты DTO проекций и SSE envelope, **freeze** (lead, Opus).
2. Acceptance-критерии, Red (lead).
3. Параллельно после freeze: проекции + миграции (persistence-implementer), долги I02B (lead).
4. Observer API (projection-api-implementer) — после проекций.
5. Экран (frontend-implementer) — после API.
6. Playwright — последним.
7. Два раунда верификации. **Ревьюеры — в собственных worktree, поднятых от проверяемого
   коммита; пока они работают, lead в общее дерево не коммитит.** Правило старое, нарушено в
   I02B его же автором.

## 10. Отклонения от этого плана

### 1. Коэффициент скорости мира — НЕ в versioned ruleset

§4.1 говорил «коэффициент — в versioned ruleset, не в коде и не в env». Сделано иначе:
версионированные данные рядом с worker-ом (`apps/worker/src/world-tempo.ts`,
`WORLD_TEMPO_VERSION`).

Причина обнаружилась при реализации. Rules bundle адресуется checksum-ом и входит в канонический
снимок — он доказывает, ПОД КАКИМИ правилами посчитан мир. Темп на канонический результат не
влияет (это и есть D2), поэтому его включение в bundle связало бы снимки с параметром, к ним не
относящимся: поворот ручки скорости менял бы checksum, и снимки, снятые до правки, объявлялись бы
несовместимыми. Мир перестал бы восстанавливаться из-за изменения темпа показа.

Это тот же довод, по которому observer-схемы не входят в schema bundle, и решать одну и ту же
развилку двумя разными способами внутри одной итерации было бы непоследовательно.

Требование §4.1 при этом выполнено по существу: значение не магическая константа в глубине цикла
и не невидимая переменная окружения — оно названо, версионировано и видно в diff.

## 9. Stop conditions

- UI читает canonical tables — STOP;
- SSE оказался единственным способом восстановить состояние — STOP;
- journey не объясним из событий — STOP;
- скорость мира изменила канонический результат — STOP.
