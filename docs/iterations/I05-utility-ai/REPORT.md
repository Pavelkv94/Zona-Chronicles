# I05 — отчёт итерации

**Требование:** SIM-03 ([11_REQUIREMENTS_TRACEABILITY](../../11_REQUIREMENTS_TRACEABILITY.md)).
**Статус:** срезы A и B выполнены; C (срыв плана), D (экран) и E (независимый review) открыты.

## 1. Что теперь делает мир

Агент сам решает, что делать, и решение становится действием. Ни одной команды человека:

```text
устал → решил отдохнуть → лёг отдыхать → вымотан → отдохнул → бодр →
решил ничего не делать → проголодался → решил поесть → поел
```

Это ровно та летопись, которую видит зритель в браузере (снято с прогона E2E).

До этой итерации усталость только росла: снять её могла лишь команда `agent.rest`, а подать её
мог только человек — которого в наблюдаемом мире нет (PR-01). Мир был устроен так, что людям в
нём становилось только хуже. Теперь у усталости впервые появляется восстановление, и появляется
оно само.

## 2. Как устроен выбор

`score(goal) = urgency - time_cost - switching_cost`, целые тысячные, коэффициенты — в versioned
ruleset (`0.4.0`). Кандидаты первого среза: `idle`, `eat`, `rest`.

Решения, которые стоило принять явно, и их основания — в
[07_MVP_MECHANICS_SPEC §6](../../07_MVP_MECHANICS_SPEC.md) и [PLAN §4](PLAN.md). Коротко:

- **исполнимость входит в отбор**, а не проверяется после: «поесть» без еды — не цель с низкой
  оценкой, а вовсе не цель;
- **срочность считается по УРОВНЮ нужды**, а не по её значению: значение — измерение, фактом
  является уровень;
- **ничья решается порядком объявления**, а `idle` объявлен первым: при равенстве мир
  предпочитает бездействие;
- **агент решает, когда для НЕГО что-то изменилось** и он свободен — периодического опроса нет;
- **цель потребляется своим шагом**: поевший агент снова празден.

Порядок «сначала поел, потом лёг» получается СЛЕДСТВИЕМ цены времени (еда мгновенна, отдых стоит
восьми часов мира), а не записан правилом.

## 3. Что нашли пробы и измерения

Три находки, ни одна из которых не была ошибкой в новом коде как таковой.

**Мировое время шло назад.** Property-тест C12 на пяти агентах: `06:30 -> 06:10`. Действие,
назначенное фактом, получает момент этого факта, а пока оно ждёт очереди, мир уходит вперёд на
действиях СОСЕДЕЙ. Дефект существовал с I04 (приём пищи планируется тем же способом), но ни одна
проба не сводила в одном мире опоздавшее действие и ушедшее вперёд время. Опоздавшее действие
теперь исполняется в текущий момент мира.

**Летопись рассыпалась при крупном шаге.** Измерено на прогоне с горизонтом в двое суток:
`goal.chosen:eat 16:48`, `agent.ate 00:00`. Такт захватывал всё, что наступило до горизонта, и
действие, назначенное при обработке раннего момента, ждало следующего такта. Теперь шаг
обрабатывает ОДИН момент мира, а цикл до горизонта живёт в `world tick` и в шаге worker-а — там,
где смысл «дойти до X» и назван.

**Два молчаливых дефекта I05-A в слое наблюдения.** Свёртка проекции не возвращала статус `idle`
по факту `agent.rested` (в каноне агент вставал, на экране оставался лежать), а чтение строки
агента сводило всё, кроме `traveling`, к `idle` (после перезапуска сборщика отдыхающий
показывался праздным). Оба нашлись при подключении цели к той же строке.

Мутационные пробы (обе стороны, каждая роняет названный тест):

| Мутация | Кто ловит |
| --- | --- |
| ничью выигрывает последний (`>=` вместо `>`) | `goals.test.ts` — детерминированный tie-break |
| цена времени округляется вниз | `goals.test.ts` — округление вверх |
| есть можно без еды | `goals.test.ts` — цель без исполнимого шага |
| смена цели бесплатна | `goals.test.ts` — порог решает исход |
| решение назначается и занятому агенту | acceptance — «занятого мир не заставляет передумывать» |
| поевший остаётся с целью «поесть» | `goals.integration.test.ts` |
| цель «отдохнуть» не даёт шага | acceptance + integration, шесть тестов |
| такт захватывает всё до горизонта | acceptance — «решение и шаг в один момент» |

## 4. Что НЕ сделано и названо

- **`plan.invalidated` производителя так и не получил.** Срыв плана и перепланирование — срез C.
  Сегодня шаг, отвергнутый доменом, оставляет агента с целью, которую некому исполнить, до
  следующего факта, меняющего набор кандидатов. Замирания это не даёт (набор меняется каждым
  переходом порога), но и починки не даёт тоже.
- **План длиной один шаг.** Шагов длиннее пока не из чего строить: «дойти до еды» требует
  источника предметов (I08).
- **Порог смены цели с прототипными коэффициентами ни одного решения не меняет** — см.
  [PLAN §12.2](PLAN.md). Механизм живой и проверен поведением на других коэффициентах.
- **Независимого review не было.** Lead не принимает собственную работу; решение gate — за
  владельцем.
