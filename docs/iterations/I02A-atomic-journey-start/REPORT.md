## 1. Что впервые стало возможным наблюдать

Мир перестал жить только внутри процесса. Команда меняет durable state атомарно, и результат
виден другому процессу:

```text
$ pnpm world init --seed 42
Мир world:prototype создан из seed=42; версия 0.

$ pnpm world run --agent agent:rook --route route:yard-to-bridge
Команда cmd_8B8S7CT1T6920H6HJVCM7MCN8S принята.
  события: evt_D2ETY739KPRAYTMXP916Q7DKTN
  версия мира: 0 -> 1

$ pnpm world state          # отдельный процесс, отдельное подключение
  agent:rook     traveling  в loc:quiet-yard по маршруту route:yard-to-bridge

$ pnpm world run --agent agent:rook --route route:yard-to-bridge --command-id cmd_8B8S...
Команда cmd_8B8S7CT1T6920H6HJVCM7MCN8S принята (повтор: результат прочитан из journal).
  события: evt_D2ETY739KPRAYTMXP916Q7DKTN

$ pnpm world events
Событий: 1
```

Мир по-прежнему не идёт сам: `journey.completed` требует scheduler-а — это I02B. Доказано, что
первый настоящий переход состояния переживает процесс, повтор и сбой.

## 7. Что стоит знать перед I02B

- **Одна команда сейчас порождает ровно одно событие.** `decide` ставит каждому событию
  `sequence = state.sequence + 1`; команда с двумя событиями упала бы на уникальном индексе
  `(world_id, sequence)` — громко, но упала бы. Снять ограничение обязана I02B вместе со
  scheduled actions.
- **Позиции PRNG не персистятся.** `UnavailableRandomSource` в handler-е бросает исключение при
  любом розыгрыше — это намеренная ловушка: первая команда, которой понадобится случайность,
  упадёт с названной причиной, а не начнёт молча повторять одно значение.
- **Новая таблица не получает грантов автоматически** (проверено исполнением). Каждая таблица
  I02B обязана принести свои `grant` в той же миграции, иначе worker получит `permission denied`.
- **`event_id` больше не свободен.** Формат зафиксирован golden-тестами: изменение — migration.
- Роли PostgreSQL — объекты кластера, а не базы; их создаёт миграция 0003 идемпотентно, но при
  восстановлении в другой кластер их придётся создать до применения грантов.
